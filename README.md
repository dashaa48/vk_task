# Тестовое задание: msgfmt (C++), ghreport (Go), интеграционные тесты (Python)

| Каталог | Часть | Содержание |
|---|---|---|
| `msgfmt/` | 1 | библиотека и CLI разметки сообщений, C++17, CMake/CTest |
| `service/` | 2 | служба `ghreport` на Go + Dockerfile |
| `api_tests/` | 3 | pytest-тесты службы как чёрного ящика + мок-сервер GitHub |

Подробности, запуск и принятые решения — в README каждого каталога.

## Быстрый запуск

```sh
cmake -S msgfmt -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build && ctest --test-dir build
(cd service && go vet ./... && go test ./... && go build -o ghreport .)
GHREPORT_BIN=$PWD/service/ghreport pytest api_tests -q
```

## Время и инструменты

* Затраченное время: заполнить при сдаче.
* ИИ-инструменты: Claude (Anthropic) — генерация и ревью кода, тестов и документации; все результаты запускались и проверялись автором (см. ниже, что именно было проверено).

## Что и чем проверено (честно)

* **Часть 1:** собрана `g++ -std=c++17 -Wall -Wextra` без предупреждений; 20 101 проверка (таблица приложения А, UTF-16, UTF-8, escape, JSON, свойства на случайных входах) и CLI-тест проходят в том числе с `-fsanitize=address,undefined`. Файл `CMakeLists.txt` в среде разработки не запускался (CMake отсутствовал), сборка проверена напрямую через g++ — перед сдачей выполнить `cmake`/`ctest` на своей машине.
* **Часть 2:** в среде разработки не было Go-компилятора, поэтому код и юнит-тесты написаны и вычитаны вручную, но **не компилировались и не запускались**; `gofmt -l`, `go vet`, `go test`, `docker build` необходимо выполнить на своей машине и исправить возможные замечания. Поведение по контракту при этом проверено эталонной реализацией на Python (см. часть 3), логика Go-кода ей соответствует.
* **Часть 3:** набор из 61 теста проходит против эталонной реализации; проверка мутациями (`api_tests/selfcheck/run_mutants.py`) подтверждает, что набор ловит нарушения контракта. Запуск именно под `pytest` в среде не делался (его там нет): использовался совместимый мини-раннер; тесты написаны на обычных фикстурах `pytest` (`tmp_path`, `yield`-фикстура, `parametrize`, `skip`).

## Решения по неоднозначностям

* `--limit` считается от подходящих элементов (после фильтров PR, `--since`, дедупликации).
* 304 без отправленного `If-None-Match` — `invalid_response`; 429 всегда лимит; обычные 403/410 — `request_failed` без повторов.
* Пример 9 приложения А расходится с текстом правил (см. `msgfmt/README.md`).
