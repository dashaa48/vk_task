# api_tests — интеграционные тесты ghreport (pytest)

Тесты запускают службу как чёрный ящик (отдельный процесс) и проверяют отчёт, журнал `--trace`, коды возврата и запросы, которые служба посылает серверу.

## Запуск

```sh
pip install -r requirements.txt
export GHREPORT_BIN=/path/to/ghreport      # собранный бинарник из service/
pytest api_tests -q
```

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `GHREPORT_BIN` | путь к исполняемому файлу службы (обязательна) |
| `GITHUB_API_BASE_URL` | необязательна; включает `test_live_server.py` против любого сервера, совместимого с контрактом (заглушка, GitHub) |
| `GHREPORT_LIVE_REPOS` | репозитории на этом сервере через запятую (по умолчанию `stub/alpha`) |
| `GITHUB_TOKEN` | необязателен; используется только в live-тестах |

Для остальных тестов `GITHUB_API_BASE_URL` задавать не нужно: каждый тест поднимает свой локальный сервер на `127.0.0.1` (`mock_github.py`, только стандартная библиотека) и передаёт его адрес службе через окружение дочернего процесса. Наружу в сеть тесты не ходят; состояние репозиториев не меняют (только GET).

## Устройство

* `conftest.py` — запуск службы (`run_ghreport`), фикстура `env` (фейковый GitHub + временные каталоги кэша и журнала). Каждый тест получает собственный каталог.
* `mock_github.py` — фейк эндпоинта `GET /repos/{o}/{r}/issues`: страницы, `Link`, `ETag`/`304`, а также сценарии отказов (`script`): 401, 403/429 с `Retry-After`/`X-RateLimit-*`, 5xx, оборванное соединение, битый JSON, 304 без `If-None-Match`, редиректы. Фиксирует все запросы (заголовки, параметры, время, число одновременных запросов).
* `test_report.py` (схема, маппинг полей, форма запроса и заголовки), `test_pagination.py` (Link, `--limit`, `--since`, PR, дубликаты, сортировка, редиректы), `test_cache.py`, `test_errors.py`, `test_ratelimit.py`, `test_trace_and_cli.py` (журнал, утечки токена, аргументы), `test_live_server.py` (сверка с «оракулом»: тест сам читает API и считает ожидаемый отчёт, поэтому данные сервера заранее знать не нужно).

Раздел 5.3 → файлы: 1 → `test_pagination`; 2 → `test_pagination`; 3 → `test_pagination`; 4 → `test_cache`; 5 → `test_ratelimit`; 6 → `test_errors`; 7 → `test_report`; 8 → `test_trace_and_cli`.

## Качество набора

* Нет произвольных `sleep` в тестах; ожидания — только те паузы, которые обязана выдержать служба (`Retry-After: 2`, backoff 1+2+4 с). Каждый запуск процесса ограничен `timeout`. Полный прогон ≈ 1–1,5 минуты.
* Тесты независимы (отдельные каталоги, отдельные серверы), порядок запуска не важен.
* Проверка на обнаружение нарушений (раздел 5.4): `selfcheck/ghreport_ref.py` — эталонная реализация контракта на Python, в которую можно «подмешать» ошибку (`GHREPORT_REF_MUTANT`). `python selfcheck/run_mutants.py` запускает набор против эталона (должен пройти) и против 19 сломанных вариантов (каждый должен быть пойман): PR без фильтрации, limit+1, ручное построение URL страниц, игнор `Retry-After`, `If-None-Match` без кэша, токен в кэше/журнале, обратная сортировка, 401 как обычная ошибка и т.д.

## Допущения

* Неоднозначные места контракта, зафиксированные тестами: `304` без отправленного `If-None-Match` — ошибка репозитория (не успех); `429` всегда считается исчерпанием лимита, `403` — только по признакам из 4.4.5; обычный `403`/`410` — `request_failed` без повторов; при ошибке на любой странице у репозитория `count = 0`, `issues = []`; `--repos` с пустым элементом (`a/b,`) некорректен (код 2).
* Паузу «не менее 60 секунд» (лимит без заголовков) тесты не проверяют, чтобы не нарушать ограничение по времени; она покрыта юнит-тестом в `service/`.
